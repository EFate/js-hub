# js-hub

## github-accelerate.js

基于 Tampermonkey / Violentmonkey 的 GitHub 下载加速、Release 页面增强与节点管理脚本（v1.5.1，单文件）。脚本安装后会在 GitHub 页面右侧注入一个可拖拽的圆形启动器，通过面板统一管理全部功能。

> **升级提示**：面板标题显示的版本即当前运行版本。更新脚本后面板仍显示旧版本号 = 浏览器里跑的还是旧代码，需在 Tampermonkey 中重新安装/覆盖脚本，并强制刷新（Ctrl+F5）GitHub 页面。

核心设计原则：**脚本只负责生成镜像直链并触发浏览器原生下载，不代理、不中转下载流量**。因此 Gopeed、IDM 等外部下载工具的接管行为不受任何影响。

作者 **EFate**。

### 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展；
2. 在 Tampermonkey 中新建脚本，粘贴 `github-accelerate.js` 全部内容并保存；
3. 访问任意 GitHub 仓库或 Release 页面，右侧出现绿色圆形启动器即表示安装成功。

### 功能一：下载加速

脚本自动识别页面中的下载入口，注入加速按钮；点击后由脚本选取可用镜像，将原始 URL 替换为镜像直链，再通过一次原生点击交给浏览器下载。

| 特性 | 说明 |
|------|------|
| 场景覆盖 | 9 类下载场景：Release 资产、源码包（tag/archive）、Raw 文件、Clone 弹框 ZIP、LFS 大文件、Gist、patch / diff 等 |
| 镜像来源 | 三级降级：公开聚合接口 A → 聚合接口 B → 内置镜像池（32 源）本地连通性测速筛选。**内置池始终并入「节点」页签统一管理**（带「内置」标签，未测速显示「未测速」），可直接勾选、单独测速或「全部测速」，测完按真实延迟重新排序 |
| 节点统一管理 | **内置源与聚合接口节点合并入同一列表**（内置源带「内置」标签）：统一勾选、筛选、单节点测速、「全部测速」；未测速显示「未测速」沉底，测后按真实延迟归位；**测挂的节点保留在池中沉底（不删除）**，内置源历史测速延迟跨刷新保留 |
| 节点管理 | 节点列表面板：刷新、全量测速、全选 / 全不选 / Top10、域名筛选、单节点测速、勾选启用 |
| 健康度管理 | 镜像连续失败 2 次即移出候选队列，恢复后自动重新入队 |
| 预检缓存 | 预检通过的镜像在 5 分钟内视为有效，后续下载跳过探测、直接发起 |
| 提示策略 | 快路径静默完成（避免提示框闪现），仅慢路径显示预检进度 |
| 手动 / 自动 | 开启「全自动下载」后自动选取最快镜像、失败自动降级；关闭时弹出节点选择弹窗手动指定 |
| 节点缓存 | 缓存有效期 1 小时，过期自动刷新；面板内支持全量手动测速，测速分批执行 |

### 功能二：Release 增强显示

针对 Release 页面资产列表的四项增强能力。各项可独立开关，配置持久化存储；开关位于面板「增强」页签，改动即时生效（个别项需刷新页面一次）。

**文件分组排序**
按 Windows / macOS / Linux / Android / iOS 对资产文件分组，组内依据当前浏览器环境（OS 与架构）计算匹配度并排序，推荐安装包置前并高亮。环境判定为启发式推测，可通过注入的 OS / 架构下拉框手动覆盖，切换后立即重新排序。

**下载量显示**
调用 GitHub API 获取各资产的下载次数并注入显示。受未登录 API 限额约束（约 60 次/小时），超限时会提示限流，稍后点击「显示下载量」即可重试。该功能与下载加速完全独立，限流不影响下载。

**精确时间**
将「2 days ago」等相对时间替换为精确格式「2026-08-30 14:22:05」。默认关闭。

**更新日志折叠**
为 Release 更新日志添加折叠控件，默认展开。

### 功能三：节点统一管理

内置镜像池与聚合接口节点**合并进同一个列表**统一管理：统一显示（内置源带「内置」标签，未测速显示「未测速」沉底）、统一勾选启用、统一测速（单节点测速 / 全部测速），测完按真实延迟归位；测挂的节点保留在池中沉底（不删除），内置源的历史测速延迟跨刷新保留。

### 性能设计（v1.5.0）

- 观察回调**禁止 HTML 序列化**：命中判断用一次 CSS 选择器子树查询（浏览器 C++ 侧执行），成本比逐节点 `outerHTML` 低约两个数量级——旧版在 GitHub 加载期对数千节点的大子树反复序列化，把主线程塞满，是页面卡顿、加载转圈的根因；
- **无常驻轮询**：初始扫描 + 路由变化 + turbo/pjax 事件 + 突变驱动已全覆盖；
- **按需拉节点**：仅缓存过期（1 小时）才请求聚合接口，打开新页面不再发多余请求；
- 调度链逐模块 try/catch 隔离，单个模块异常不拖垮其余功能。

### 使用说明

| 操作 | 方式 |
|------|------|
| 加速下载 | 页面下载位置出现加速按钮，点击即可；首次或缓存过期时有一两秒预检 |
| 管理节点 | 面板「节点」页签：刷新、测速、勾选常用镜像（默认取最快 10 个） |
| 全自动下载 | 设置中开启后自动选最快镜像直发、失败自动换；关闭则每次弹窗手选 |
| 呼出面板 | 启动器隐藏时，通过油猴菜单「打开加速面板」呼出；「显示侧边启动器」控制显隐 |

### 设置项

| 设置 | 默认 | 说明 |
|------|------|------|
| 全自动下载 | 关 | 开启后自动选取最快镜像直发；关闭后每次下载弹出手选弹窗 |
| 自动刷新节点 | 开 | 启动时检查节点缓存，超过 1 小时自动重新拉取 |
| 显示侧边启动器 | 开 | 关闭后仅能通过油猴菜单「打开加速面板」呼出面板 |
| 显示页面内镜像按钮 | 开 | 关闭后页面内不注入加速按钮，仅保留启动器入口 |

### 代码结构

脚本采用七层架构组织，依赖自上而下单向：配置（L1，含内置镜像池）→ 基础工具（L2）→ 网络（L3）→ 状态持久化（L4）→ 能力（L5）→ 界面（L6）→ 启动流程（L7）。L5 能力层不反向依赖 L6——页面按钮的下载入口由 L7 装配层注入（Injector.onDownload），跨层交互只有装配一条路。

- **基础层**含一组纯函数模块：Arch（平台/架构判定，无 DOM 依赖）；
- **能力层**三个模块：Downloader（直链交付）、Injector（规则表注入）、Enhancer（Release 增强）；
- **启动层**的 Watcher 是全脚本唯一的 DOM / 路由监听者（单 MutationObserver + turbo/pjax 事件，无常驻轮询），统一驱动 Injector / Enhancer 重扫；模块只暴露幂等的 `run` / `scan`，不再各自建监听器。

完整分层见 `architecture-diagram-svg/github-accelerate-architecture.svg`。

### 常见问题

**点了下载没反应？**
脚本只做一件事，把镜像直链用一次原生点击交给浏览器，后面归浏览器管。装了 Gopeed 扩展就由它拦截，没装就进浏览器自带下载器。

```
脚本点击 <a download>
        │
        ▼
  浏览器原生下载事件
        │
   ┌────┴────┐
   ▼         ▼
默认下载器   Gopeed 扩展拦截
```

还不行的话，多半是镜像不支持这个文件。弹窗里有「复制链接」，粘到下载工具里直接下。

**镜像为什么有时快有时慢？**
镜像列表来自公开聚合接口，按实测延迟排序，缓存一小时；聚合接口全部失效时自动退回内置镜像池（32 源）本地测速兜底。下载失败会自动换下一台，不用手动管。内置池均为长期维护的公益加速源，节点长期失效时可直接增删源码中的 `BUILTIN_MIRRORS`。

**下载量不显示，或者提示获取失败（限流）？**
数据来自 GitHub API，未登录一小时大约 60 次。超了就等一会儿，再点「显示下载量」。

**切换 OS / 架构下拉没反应？**
先确认「文件分组排序」开关是开着的。开着的条件下，切换下拉会立即重排所有已加载的 Release 文件列表，比如选了 macOS，.dmg 会排到最前。

**分组排序会影响加速下载吗？**
不会。增强显示只动页面展示，顺序、标签、下载量都是显示层的活，下载照旧走镜像直链。
