# js-hub

## github-accelerate.js

GitHub 镜像加速下载 + Release 增强显示 的油猴脚本（v1.0.0 · 无感版，Tampermonkey / Violentmonkey）。自动在 GitHub 页面注入加速按钮，一键把下载换成镜像直链，**脚本本身不接管下载**——只挑镜像、给直链，下载一律交给浏览器原生通道，**Gopeed / IDM 等接管工具可正常工作**。另集成社区 Release 增强显示能力（文件分组排序、下载量、精确时间、日志折叠）。作者：**EFate**

### 功能特性

- 自动识别 GitHub 页面上的下载场景（Release 资产 / Raw 文件 / 仓库归档 / Gist 等 9 类），一键注入加速按钮
- 纯直链交付：脚本不下载、不中转、不占内存，选中镜像后直接走浏览器原生下载，下载工具随时接管
- 双节点接口源 + 内置镜像测速兜底，一个接口挂了自动切换下一个
- 镜像健康度记忆：坏镜像失败自动剔除、恢复后自动回队，不再反复踩坑
- 镜像新鲜度缓存：预检过的镜像在 5 分钟内视为 fresh,直接 0ms 直发,跳过预检等待;失败自动换下一个
- 反馈不打扰：快路径不弹过程提示（避免一闪而过的闪烁），仅慢路径才展示预检进度
- 下载时可选「节点选择弹窗」手动挑镜像,或关闭它进入全自动模式(自动选最快镜像、失败自动换下一个)
- 右侧居中的可拖拽启动器（默认贴右，可拖到任意位置），四页签面板：节点管理 / 注入开关 / 偏好设置 / **增强显示**
- **Release 增强显示**（可逐项开关，持久化）：
  - **文件分组排序**：Release 资产按平台（Windows / macOS / Linux / Android / iOS）分组，按当前系统/架构排序，高亮最可能安装的包；并提供 OS / 架构手动切换下拉
  - **下载量**：通过 GitHub API 显示各文件下载次数（受 API 限流影响，可刷新）
  - **精确时间**：把「2 days ago」相对时间替换为「YYYY-MM-DD HH:MM:SS」
  - **日志折叠**：给 Release 更新日志增加折叠开关，默认展开

### 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)
2. Tampermonkey → 添加新脚本 → 粘贴 `github-accelerate.js` 全部内容 → 保存
3. 打开任意 GitHub 仓库 / Release 页面，右侧出现绿色圆形启动器即生效

### 使用

- **下载文件**：页面上出现加速按钮（或点右侧启动器），点击即可下载；首次或长时间未用会有 ≤ 2.5s 预检；之后因新鲜度缓存命中 → 点完即发，无延迟
- **全部测速**：面板「全部测速」批量预热节点且只写盘 2 次，30 个节点也不卡顿
- **全自动直发**：设置里开启「全自动下载」，之后自动选最快镜像直发（无感），失败自动换下一个；关闭则每次下载先弹窗手选
- **管理节点**：面板「节点」页签可刷新、测速、勾选常用镜像（默认取最快的 10 个）
- **增强显示**：面板「增强」页签可逐项开关四大能力（文件分组排序 / 下载量 / 精确时间 / 日志折叠），改动即时生效并写盘；部分需刷新页面
- **找不到了**：关闭启动器后，通过油猴菜单「打开加速面板」呼出；「显示侧边启动器」开关可随时控制显隐

### 设置项

| 设置 | 默认 | 说明 |
|------|------|------|
| 全自动下载 | 关 | 开 = 自动选最快镜像直发（无感）；关 = 每次下载弹窗手选镜像 |
| 自动刷新节点 | 开 | 启动时检查节点缓存是否过期（缓存 1 小时） |
| 显示侧边启动器 | 开 | 关闭后可用油猴菜单「打开加速面板」呼出 |
| 显示页面内镜像按钮 | 开 | 关闭后 GitHub 页面不出现注入加速按钮，只能用启动器手动打开弹窗 |

### 增强显示设置项

| 设置 | 默认 | 说明 |
|------|------|------|
| 文件分组排序 (groupSort) | 开 | 按平台分组、按当前系统/架构排序，高亮最可能安装的包；含 OS / 架构手动切换下拉 |
| 显示下载量 (downloadCount) | 开 | 通过 GitHub API 显示各文件下载次数（受 API 限流影响，点「显示下载量」按钮获取/刷新） |
| 相对时间替换 (replaceTime) | 关 | 将「2 days ago」替换为「YYYY-MM-DD HH:MM:SS」 |
| 更新日志折叠 (collapsibleNotes) | 开 | 给 Release 更新日志增加折叠开关，默认展开 |

> 以上开关可在面板「增强」页签或油猴菜单「★ 增强：…」中切换，全部持久化于 `Settings.enhance`。

### 集成说明（v1.0.0 新增）

v1.0.0 从社区脚本 `github增强显示.js`（caolib）提取了四类核心能力并合理化集成，而非简单拼接：

- **纯计算** 归入新增的 **L2-b Arch** 纯函数层（文件名 → 平台/架构/分组、当前环境 → OS/架构、计数格式化），不触碰 DOM；
- **DOM 编排** 归入新增的 **L5-c Enhancer** 能力层（扫描、注入控件、分组排序、下载量注入、架构说明弹窗）；
- 四项能力均可独立开关、持久化于 `Settings.enhance`，默认仅 `replaceTime` 关闭；
- **主动排除**与原脚本冲突/冗余的部分：依赖 XIU2 脚本的代理下拉、与右侧启动器位置冲突的「回到顶部」按钮。

### 常见问题

**点了下载没反应？**
脚本只负责把镜像直链通过原生 a[download] 点击推到浏览器，下载事件由浏览器原生通道交给默认下载器或 Gopeed 浏览器扩展，脚本不接管下载。链路如下：

```
脚本（只管「发射」）
  │
  ▼
  <a download> 原生点击 ──→ 浏览器原生下载事件
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
        浏览器默认下载器                  Gopeed 浏览器扩展拦截
        （没装 Gopeed 时）                （chrome.downloads 监听）
```
若浏览器仍无反应（例如镜像不支持该文件），弹窗里有「复制链接」，粘贴进下载工具直接下即可。

**镜像为什么有时快有时慢？**
镜像列表来自公开聚合接口并按实测延迟排序，缓存 1 小时；下载失败会自动换下一个镜像，无需手动干预。

**下载量为什么不显示 / 显示「获取失败(限流)」？**
下载量来自 GitHub API（`/releases/tags/<tag>`），未登录调用有速率限制（约 60 次/小时）。点「显示下载量」按钮获取；若提示限流，稍后重试即可。该能力完全独立，不影响镜像加速。

**分组排序后为什么切换 OS / 架构下拉没反应？**
切换下拉会即时按所选 OS/架构重新排序（例如当前是 macOS，则把 `.dmg` 排到最前）。若曾关闭又开启「文件分组排序」，需确保该开关为开；切换后会立即重排所有已加载的 Release 折叠块。

**「文件分组排序」和原来的加速下载冲突吗？**
不冲突。增强显示只做页面展示层的分组、标签、下载量、时间替换，下载仍走原有镜像加速直链链路，脚本依旧不接管下载。
