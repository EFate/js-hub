# 变更日志 · jump-hub

格式：`版本 — 日期` 一行结论，下面列具体改动与验证证据。

## v1.3.0 — 2026-09-21

**用户反馈**：「touchgal.ink 这个网站明显后两个没接管。应该所有网站都能识别，不限于指定网站，但是一定要确保没有错误，正确的准确是最重要的。」

一句话：**把「站点名单」从主干降为加速，通用识别上位；顺手修掉一个张冠李戴的取码 bug。**

### 一、根因定位（先复现，不猜）

抓下线上真实 HTML（`https://www.touchgal.ink/c5779e63/resource/47769`，Next.js SSR），
装进 jsdom 跑真实脚本，把 6 条相关链接逐条打点，得到两个独立缺陷：

| # | 现象 | 根因 |
|---|---|---|
| **B1** | 正文里无码的夸克 / UC 链接，被凭空加上了 `?pwd=dlam` | `findNearbyPwd` 往上爬时越过了「这一条自己的块」，爬到**三条链接共用的段落容器** `<div class="kun-prose">`，把隔壁百度链接的码当成了自己的 |
| **B2** | 已带码的链接（`pan.baidu.com/s/1_2FZy...?pwd=dlam`）看起来像「没接管」 | ① `netdiskTarget` 对已带码链接返回 `null` → ② `deepScan` 里 `if (!to) continue` 直接跳过 → ③ 这条链接**从不落标记**，点击层也就无从接管 |
| **B3** | **主干缺陷**：异步渲染出来的链接，首屏扫描之后**再没人管** | `MutationObserver` 回调只调 `scan()`，而 `scan()` 第一行就是 `if (!rule || !rule.rewrite) return 0` —— 未适配站点没有规则，**整个观察器空转**；而能处理未适配站点的 `deepScan()` 只在 `DOMContentLoaded` 跑一次 |

B3 就是「后两个没接管」的真凶：页面是 SPA，下载卡片在水合之后才插入 DOM，
首屏那一次 `deepScan` 什么也没看到。

### 二、修法

**① 通用识别上位（架构调整）**

- 抽出 `resolveLink(a)` 作为**单链接处理的唯一入口**，与站点规则无关
- `deepScan()`（首屏全量）与 `scanRoot()`（异步增量）**共用**它 —— 两边逻辑不会再漂移
- 站点规则命中则先走确定性改写，**没命中也照常工作**

**② 新增增量扫描**

```js
const pendingRoots = [];          // 新增节点队列
function queueNode(node) { ... }  // MutationObserver 把 addedNodes 入队
function scanRoot(root) { ... }   // 只扫这一棵新子树，走 resolveLink
function flushRoots() { ... }     // 按帧批量消费，断开的节点跳过
```

`MutationObserver` 回调里：站点规则那部分仍走 `scan(document)`，其余新增子树交给 `flushRoots()`。

**③ 提取码归属判定**

`findNearbyPwd` 往上爬时，每上一层先问一句「这个容器里除了我，还有别的网盘分享链接吗？」

```js
if (i > 0 && hasSiblingPanLink(el, anchor)) break; // 进入公共容器，停止
```

有 → 说明已经越过了「这一条自己的块」，**里面的码不专属于谁，立即停止**。
只认网盘链接（不是所有外链）—— 卡片里放个「官方教程」链接不影响判断。

**④ 已带码的链接也要落标记**

新增 `isPanShare(a, href)`：只要是网盘分享页（无论有没有码）都落 `data-jh` 标记，
让点击层知道「这条处理过了」。地址一个字符不改，只是不让站点把它改道。

**⑤ 点击层不再因为 `defaultPrevented` 放弃**

原来的 `if (e.defaultPrevented) return;` 会让 React / Vue 站点上「站点先跑一遍处理器」
的链接直接漏掉接管。**站点抢先 `preventDefault` 往往正是它在拦这次点击** —— 该接管而不是让出去。
「自己人」由 `data-jh-bypass` 标记挡掉，不会自拦。

## v1.2.0 — 2026-09-21

**用户反馈**：「已带上 / 已提取这种成功的没必要提示，而且应该是新页标签打开，操作尽量无感。整体设置很多功能，有些功能介绍不简洁清晰，且有些开关思考有必要吗，同类功能恰当展示。」

也就是三件事：**成功不提示** · **新标签打开** · **设置的信息架构重做**。

### 一、成功类提示全部删除

| 删掉的提示 | 原本什么时候弹 |
|---|---|
| 「已带上「百度网盘」提取码 k9x2」 | 点网盘链接带了码 |
| 「已自动填入「百度网盘」提取码」 | 落在分享页自动填了码 |
| （上一版已删）「已跳过中转页，直达 xxx」 | 免中转跳转 |

判据：**成功的操作不提示** —— 人已经到地方了，结果自己会说话。提示只保留两处：**首次安装那一次**（否则没法确认脚本是否生效）、**面板里主动点按钮的反馈**（用户主动操作，理应有回应）。

代价与取舍：`轻提示` 这个设置项随之失去意义，一并删除（它已成为「只控制一条一次性提示」的空开关）。

对应新增静态护栏：冒烟第 11 组按**大括号配对抠出函数体**，断言 `onClick` / `autoFill` / `tryAutoJump` / `netdiskTarget` / `scan` / `deepScan` 的函数体里**一个 `toast(` 都不许有**（不是全文搜，防止误判）；端到端场景 7f 触发一次带码 + 一次免中转，等足 1.4 秒后断言 toast 容器里**零个** toast，同时统计照常计数。

### 二、统一在新标签页打开

以前只有 `target="_blank"` 或 ctrl / 中键才开新标签，其余会把当前页导航走。现在**拦截后一律开新标签**，原页面留着。

实现上有两处讲究：
- 优先 `window.open`；被拦或返回 falsy 时，退到**合成一个 `<a target="_blank" rel="noopener">` 再点它** —— 真实链接点击不会被弹窗拦截器挡掉，而且 `noopener` 不给目标页 `opener` 权限
- 合成链接打 `data-jh-bypass` 标记，点击守卫见到就放行，**免得自己拦截自己**（死循环）

新增 `在新标签页打开` 开关（默认开），想原地跳可以关掉。

### 三、设置的信息架构重做：10 个开关 → 5 个，分 4 组

尺子是一条：**一个开关存在的唯一理由是「用户会在某个场景下真想关掉它」**。

**删掉 4 个（实现细节，用户只要结果）**

| 删掉的 | 理由 |
|---|---|
| 改写页面跳转链接 | 「改写 href 还是拦截点击」是脚本内部的事 |
| 页面链接预解析 | 唯一可见收益是中键 / 右键也免中转，那本来就该默认有 |
| 网盘分享页自动填提取码 | 与「自动带码」是同一件事的第二步 |
| 填码后自动提交 | 同上第三步；「填了还要手动点提交」本身就和无感冲突 |

**合并 4 个 → 2 个（同一次用户意图只给一个开关）**

- `压掉站点拦截` = 原「点击时接管」+「接管 window.open」 —— 都是「别让站点抢走这次点击」
- `自动带提取码` = 原「自动带码」+「自动填码」+「自动提交」 —— 都是「提取码这件事」

**最终 5 个开关 / 4 组**：主开关（总开关）· 跳转行为（在新标签页打开 / 落地中转页自动跳走 / 压掉站点拦截）· 网盘（自动带提取码）· 站点。

**顺手改掉一处「反人类」交互**：原来的「不处理名单」是一个要手打逗号分隔域名的文本框。现在改成**一键开关**（`本站不处理`，旁边标出当前站点）+ 可点删除的标签列表 —— 和「站点规则逐条停用」是同一套交互，同类功能恰当展示。

**旧设置自动迁移**，升上来不用管：`takeover` / `openHook` 任一关过 → `guard` 关；`panCode` / `panFill` 任一关过 → `panAuto` 关；迁移完旧键直接丢掉，不留幽灵设置（端到端场景 8f 逐条验证）。

### 四、架构图重绘

`architecture-diagram-svg/jump-hub-architecture.svg` 改成 **680×800**，顶部加了一条**「用户只做一件事：点一下链接」**的主线带（这是全部设计的前提），③ 执行层加入「新标签打开」，⑤ 面板层改为反映新的设置架构（2 Tab / 设置 4 组 / 自动行为零提示）。

新增/改写的测试：

- **冒烟第 10 组 · 设置收敛**：布尔开关必须恰好 5 个且就是那 5 个键；8 个旧键必须彻底不存在；迁移映射逐条验证
- **冒烟第 11 组 · 无感**：自动行为函数体里不许有 `toast(`；`toast()` 不再受设置项控制；新标签实现必须带 `noopener` 与 bypass 标记
- **端到端 7f · 零提示**：见上

### 与仓库 UI 规范的一处偏差（有意）

`design-system/ghb-ui-spec.md` 要求「首次提示必须能在设置中关闭」。本版**删掉了提示开关**，首次安装提示改成不可关闭的一次性 toast。理由：它只出现一次、2.6 秒自动消失，为它保留一个设置项本身就是「多余的开关」。若后续被反馈打扰，再补回。

## v1.1.0 — 2026-09-21

**用户反馈**：「我不想选取文字跳出弹窗，这样太麻烦了。我想直接点击链接，就访问到任何网站，包括网盘。」

也就是：不要「选文字 → 识别 → 出结果 → 再打开」这套中间步骤，**点一下就到地方**。

### 移除（做减法）

**整条「选文字识别」链路拆掉** —— 它是从参考实现带过来的交互模型，与「点一次就到」的目标冲突：

| 移除项 | 原用途 |
|---|---|
| 面板第三个 Tab「网盘直达」 | 粘文本 / 读剪贴板 / 识别选中 → 结果列表 → 打开 / 复制 |
| 「识别选中」「读剪贴板」「识别框内内容」按钮 | 手动触发识别 |
| 管理器菜单「识别选中文字里的网盘链接」 | 菜单里的同一入口 |
| `readFromSelection` / `readFromClipboard` / `doScanText` / `openPanLink` / `copyText` / `findPanLinks` / `panState` / `panHTML` | 配套实现，一并清掉 |
| `gm.clip()` 与 `@grant GM_setClipboard` | 只有「复制」按钮在用，现在没有消费者了 |
| CSS `.jh-area` | 文本框样式 |

面板从 3 个 Tab 收敛为 **2 个（概览 / 设置）**，并在概览里加了一张「怎么用」卡，明写：**直接点链接就行**。

### 新增（全自动取码）

**点网盘链接时自动带上提取码** —— 这是补上的关键能力。此前只有 URL 里已经带了 `pwd` 时才填码；现在链接本身不带码也能直达。

提取码的三级取值（`findNearbyPwd`）：

| 优先级 | 策略 | 解决什么 |
|---|---|---|
| ① | **就近**：从被点的链接往上最多 4 层、文本量 ≤900 字的块 | 一个帖子多个网盘链接、各带各的码时，分清谁是谁 |
| ② | **整页唯一**：全页只有一个码时直接采信 | 链接旁边没写、帖子开头写了「本贴统一提取码」 |
| ③ | **歧义不猜**：多个不同码 + 就近找不到 → 什么都不做 | 猜错比不填更糟 |

性能上加了闸门：`pagePwds()` 整页扫一次并缓存（`MutationObserver` 触发时失效），页面上压根没有码时（绝大多数页面）逐链接的祖先遍历**整段跳过**。

**统计口径归一**：只要**终点**是带码的网盘链接，就记「已带提取码」—— 这样「点击时现拼」与「预解析先拼好、点击时只是接管」两条路径的数字一致，用户感知到的都是「点一下就到、码已经在了」。

**提示进一步收敛**：免中转的「结果」是看得见的（人已经到目标站了），**不再弹提示**；只有「已带上提取码」才给一条 2 秒提示（需要让用户知道码的来源，也可能抓错）。同时新增手动兜底：「重新扫描本页」（面板按钮 + 菜单命令）。

### 修复

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 英文正文里的 `key word` / `password below` 被当成提取码 | 单一正则把中文标签和拉丁标签混在一起、都允许不带分隔符 | 拆成三组模式：中文标签可不带分隔符；拉丁标签**必须带 `:` 或 `=`**；并**不再收 `key`**（误报率高于收益） |
| 2 | 场景 9 出现「别的站点规则改写了本场景的链接」 | 测试环境：脚本的延迟回调按调用时读取全局 `document`，上一条场景遗留的 `requestAnimationFrame` 打进了新场景的文档 | 测试侧修：每条场景装载前先 `window.close()` 掉上一个窗口，连定时器 / rAF 一起掐掉（`await settle()` 盖不住所有动态回调） |

## v1.0.0 — 2026-09-21

初版。把「点链接先落中转页、还得再点一次、网盘还要手输提取码」这条四步路压成一步。

### 新增

**四层架构，四条出口层层兜底**

| 层 | 内容 |
|---|---|
| 触发层 | `MutationObserver` 页面扫描 · `click` 捕获拦截 · `window.open` 包装 · 落地自检 |
| 解析与判定层 | 49 条站点规则表 · 通用跳转参数表 · 多层解码 · 幂等 `resolveTarget()` · 同域排除 · 中转页评分 |
| 执行层 | 改写 `href`（首选）· 点击拦截（兜底）· `location.replace` 自跳 · 网盘带码 URL |
| 网盘增强层 | `parsePwd()` · `autoFill()` · `readSelection()` |

**外链免中转**

- 49 条站点规则：搜索引擎 7 条、社区 / 博客 24 条、内容 / 分享 / 文档 8 条、社交 / 海外 10 条
- 通用参数兜底：未适配站点靠 `STRONG_PARAMS` / `WEAK_PARAMS` 也能生效
- 多层解码：percent 最多回溯 3 层、`base64`（含 URL-safe 与 `a1` 前缀）、协议相对补全、中文句号归一、零宽字符清理
- `resolveTarget()` **幂等** —— 已是目标地址的输入原样返回。这条性质让「改写」与「点击拦截」共用同一段逻辑而不互相打架
- 深度预解析：空闲时批量改写页面里的 `a[href]`（上限 2000 条），让**中键新标签、右键「在新标签页打开」**同样免中转
- 中转页评分制自动跳转（阈值 60），站点规则未覆盖的拦截页也能自动走人

**OAuth 护栏（本次设计的重点取舍）**

`?redirect_uri=` / `?return_url=` 这类是授权链接参数，当外链改写会直接打断登录流程。因此参数表分两级：高置信参数出现即采信，低置信参数（含全部 `*_url` 形态）**只在页面本身就是跳转页时才采信**。同时「无 key 裸拼 URL」（`/transfer?<url>`）的兜底也加了同样的门控 —— 这条是最初实现里的真实缺陷，被端到端场景 3 抓出来后才补上。

**网盘带码直达**

- 识别 21 家网盘（百度 / 夸克 / UC / 阿里 / 微云 / 蓝奏云 / 123 / 4275 / 移动 / 联通 / 天翼 / 迅雷 / 115 / 360 / 奶牛快传 / 城通 / 文叔叔 / 微盘 / 坚果云 / MEGA / FlowUs）
- 分享页自动填码并提交，兼容 React / Vue（走 `_valueTracker` + `input` / `change` / `keyup` 三连）
- **脚本写 `pwd` 参数、脚本读 `pwd` 参数** —— 不依赖各家网盘是否认这个参数名，认就直接进、不认就代填
- 只加 query、**不动 hash**，避免破坏 `drive.uc.cn/s/xxx#/list` 这类 hash 路由
- 提取码识别：中英文冒号、无冒号、`pwd=`、URL 参数、hash 纯码；且**不会**把天翼云盘的 `?code=<分享ID>` 误判成提取码
- 通用输入框兜底带门控：只有页面文本确实写着「提取码 / 访问码 / 密码」且全页只有一个可见输入框时才认，避免在网盘首页把搜索框当码框填了

**入口与界面（遵循 `design-system/ghb-ui-spec.md`）**

- 不悬浮、不占全局快捷键；网盘页把入口注入宿主既有工具栏容器（`MutationObserver` 等容器 + 防重复），管理器菜单永远兜底
- `jh-` 前缀独立样式体系：变量 / 圆角 6·14px / 字号 13·12·11 / 动效 .15·.18·.22 / 层级 `2147483000+n`
- 面板懒挂载、三张页（概览 / 网盘直达 / 设置）、`Esc` 与遮罩可关闭
- 设置项 10 个开关 + 入口配色三档 + 49 条规则逐条停用 + 不处理名单
- 「结果在面板里看得见的就不弹 toast」：预改写与点击接管只计数不打扰，只有实时拦截与自动填码才给一条 2 秒提示

### 工程

- 零第三方依赖、零网络请求（不引 `@require`，不调 `GM_xmlhttpRequest` / `fetch`）
- UMD 导出：Node 里 `require` 真实脚本直测，测试跑的是生产代码而不是副本
- 测试文件与产物：`test/smoke.js`（140 项）、`test/e2e.js`（66 项 / 10 场景）、`test/preview.js` → `preview.html`

### 测试抓出来的真实缺陷（已修）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | OAuth 链接被当外链改写 | 「无 key 裸拼 URL」兜底没有跟跳转路径绑定 | `rawInnerUrl()` 增加 `allowKeyed` 门控：带 key 的形态只在跳转页采信 |
| 2 | `/link2/` 不算跳转路径 | 路径正则用 `\b` 收尾，`link2` 的 `2` 是词字符导致不匹配 | 改为 `\d{0,3}(?![a-z])` |
| 3 | 注入入口时报 `bar.querySelector is not a function` | `waitFor()` 收到数组时把数组本身当成容器传给了回调 | 入参统一归一为选择器数组，先解析出元素再回调 |
| 4 | 网盘自动填码填到了容器 `div` 上 | 选择器列表里有容器选择器，`querySelectorAll` 文档序取到 `div`；且 `isVisible()` 在无布局环境（jsdom）恒判不可见 | 逐个选择器试且只接受 `INPUT` / `TEXTAREA`；`isVisible()` 先探测环境有无布局引擎，无布局时退化为「挂在文档上即可见」 |
| 5 | 顶层死函数 `currentPanLink` | 写了但从未使用 | 删除（仓库约定不留幽灵代码） |
| 6 | `opt.entry` 只读不写 | 有默认值但没有界面 | 补上面板里的三档配色控件 |

### 已知限制

见 README「已知限制」一节。要点：短链解析不了（不发网络请求）、站点改版会让注入入口失效（菜单兜底）、同注册域一律不跳（宁可少跳不可跳错）、点击接管会屏蔽站点埋点（可关）。
