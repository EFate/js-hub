# js-hub

## GitHub 加速助手（github-accelerate.js）

一款基于 Tampermonkey / Violentmonkey 的 GitHub 下载加速与 Release 页面增强脚本。安装后 GitHub 页面右侧会出现一个可拖拽的圆形启动器，全部功能通过面板统一管理。

- **给谁用**：需要在国内网络环境下高速下载 GitHub Release 附件、源码包、Raw 文件的开发者；
- **解决什么**：GitHub 直连下载慢或失败、Release 资产列表杂乱难找对应平台的安装包、镜像质量参差且无法观测；
- **怎么工作**：脚本只负责挑选可用镜像并生成直链，通过一次原生点击交给浏览器下载，**不代理、不中转下载流量**，Gopeed、IDM 等外部下载工具的接管不受任何影响。



### 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展；
2. 在 Tampermonkey 中新建脚本，粘贴 `github-accelerate.js` 全部内容并保存；
3. 访问任意 GitHub 仓库或 Release 页面，右侧出现绿色圆形启动器即表示安装成功。

### 功能

#### 镜像加速下载

自动识别页面中的下载入口并注入「镜像下载」按钮，点击后自动选取可用镜像、生成直链并交给浏览器下载。

| 特性 | 说明 |
|------|------|
| 场景覆盖 | 9 类下载场景：Release 资产、源码包（tag/archive）、Raw 文件、Clone 弹框 ZIP、LFS 大文件、Gist、patch / diff 等 |
| 镜像来源 | 三级降级：聚合接口 A → 聚合接口 B → 内置镜像池（32 源）本地测速筛选，接口全挂也有可用节点；另可添加自建节点 |
| 健康度管理 | 镜像连续失败 2 次即移出候选队列，恢复后自动重新入队 |
| 预检缓存 | 预检通过的镜像 5 分钟内直接发起，跳过重复探测 |
| 全败降级 | 一轮预检全部失败后 1 分钟内跳过逐个预检直接放行最快节点，避免每次下载都白等一轮 |
| 手动 / 自动 | 开启「全自动下载」后自动选最快镜像、失败自动换；关闭时弹窗手动指定节点 |
| 提示策略 | 快路径静默完成，仅慢路径显示预检进度，不打扰正常浏览 |

#### 节点统一管理

内置镜像池、聚合接口节点与自建节点合并进同一个列表，在面板「节点」页签统一管理：

- 内置源带「内置」标签和地区徽章（美国 / 香港 / 日本 / 多国等），未测速的显示「未测速」并沉底；
- 自建节点：在「节点」页签输入地址点「添加」即可入列，与内置源同样参与测速、勾选和候选排序，可随时删除；
- 支持刷新节点、单节点测速、「全部测速」、全选 / 全不选 / Top10、域名筛选、勾选启用；
- 测速后按真实延迟重新排序；测挂的节点保留在池中（不删除）并显示「不可达」，下载成功或再次测速通过即自动恢复，内置源与自建源的历史测速结果跨刷新保留；
- 节点缓存有效期 1 小时，过期自动刷新。

#### 均衡策略

候选镜像按延迟分档（快 / 中 / 慢）后档内随机选取：整体仍优先使用快档节点保证下载体验，但延迟相近的节点之间随机分流，避免所有用户集中在同几个最快节点上把公益源打爆——单源压力更小，整体可用性更稳。

#### Release 增强显示

针对 Release 资产列表的四项增强能力，均可在面板「增强」页签独立开关，配置持久化保存，改动即时生效：

| 能力 | 作用 |
|------|------|
| 文件分组排序 | 按 Windows / macOS / Linux / Android / iOS 分组，按当前系统与架构排序、高亮推荐安装包，支持手动切换 OS / 架构 |
| 显示下载量 | 调用 GitHub API 显示每个文件的下载次数（未登录约 60 次/小时，超限稍后重试即可） |
| 精确时间 | 将「2 days ago」替换为「2026-08-30 14:22:05」，默认关闭 |
| 更新日志折叠 | 为更新日志添加折叠控件，默认展开 |

### 使用说明

| 操作 | 方式 |
|------|------|
| 加速下载 | 页面下载位置出现「镜像下载」按钮，点击即可；首次或缓存过期时有一两秒预检 |
| 管理节点 | 打开面板「节点」页签：刷新、测速、勾选常用镜像（默认取最快 10 个），也可添加 / 删除自建节点 |
| 全自动下载 | 设置中开启后自动选最快镜像直发、失败自动换；关闭则每次弹窗手选 |
| 呼出面板 | 点击右侧圆形启动器；启动器隐藏时通过油猴菜单「打开加速面板」呼出 |

### 设置项

| 设置 | 默认 | 说明 |
|------|------|------|
| 全自动下载 | 关 | 开启后自动选最快镜像直发；关闭后每次下载弹窗手选 |
| 自动刷新节点 | 开 | 启动时检查节点缓存，超过 1 小时自动重新拉取 |
| 显示侧边启动器 | 开 | 关闭后仅能通过油猴菜单「打开加速面板」呼出面板 |
| 显示页面内镜像按钮 | 开 | 关闭后页面内不注入加速按钮，仅保留启动器入口 |

### 增强显示开关

| 开关 | 默认 | 说明 |
|------|------|------|
| 文件分组排序 | 开 | 按平台分组、按当前系统架构排序、高亮推荐包，附 OS / 架构手动切换 |
| 显示下载量 | 开 | 走 GitHub API，受未登录限流约束，点击按钮获取或刷新 |
| 相对时间替换 | 关 | 将相对时间替换为精确格式 |
| 更新日志折叠 | 开 | 更新日志可折叠，默认展开 |

### 油猴菜单

以 emoji 前缀按功能域分组：🚀 面板与节点 ｜ 👁⚡ 界面与下载 ｜ ✨ 增强（分组排序 / 下载量 / 精确时间 / 日志折叠）｜ ⚙️ 重置。开关项实时显示「：开 ✓ / ：关」状态，切换后自动刷新菜单。

### 常见问题

**点了下载没反应？**
脚本把镜像直链用一次原生点击交给浏览器，之后由浏览器接管：装了 Gopeed 扩展就由它拦截，没装就进浏览器自带下载器。仍不行多半是镜像不支持该文件，弹窗里有「复制链接」，粘贴到下载工具中直接下载。

**下载时页面转圈、卡顿？**
v1.5.0 起已做过专项性能优化：脚本自身保持轻量静默，不拖慢页面加载，也不在后台频繁发请求。若仍有卡顿，按 F12 打开控制台，把 `[ghBoost]` 开头的日志发给作者排查。

**镜像为什么有时快有时慢？**
镜像列表来自公开聚合接口，按实测延迟排序并缓存一小时；接口全部失效时自动退回内置镜像池（32 源）本地测速兜底。下载失败会自动换下一台，无需手动干预。内置池均为长期维护的公益加速源，节点长期失效时可在源码的内置镜像池中自行增删。

**下载量不显示，或提示获取失败（限流）？**
数据来自 GitHub API，未登录一小时约 60 次。超限后稍等片刻，再点「显示下载量」即可。

**切换 OS / 架构下拉没反应？**
先确认「文件分组排序」开关已开启。开启时切换下拉会立即重排所有已加载的 Release 文件，例如选 macOS 后 .dmg 会排到最前。

**分组排序会影响加速下载吗？**
不会。增强显示只改变页面展示（顺序、标签、下载量），下载始终走镜像直链。
