# 变更日志 · zhihu-enhance

## v1.4.1 — 2026-09-23

一句话：**用户确认「现在好了」，但反馈左右留白太多 —— 把「只解上限」补成「真的撑宽」，阅读上限提到 1500px 并随视口自适应。**

### 根因（v1.4.0 的残留缺口）

1. **只解宽度上限、不撑宽度** —— 原先只清 `max-width`、把内联 `width` 改成 `auto`，从不处理被 CSS 类写死的列宽。真实页面里正文列的窄来自**自身计算宽度（690px 量级）**，于是居中生效、左右仍各留一大片空白。
2. **`width: auto` 方向是反的** —— 在 flex 行内 `width:auto` 会缩成内容宽度，越改越窄。
3. **阅读上限本身偏窄** —— 1000px 在宽屏上仍显空。

### 修复

- **新增几何加宽分支**：祖先链上「明显窄于父级可用宽度」的列一律撑满 —— 父级是 row 方向 flex 容器用 `flex-grow`（能填平 `flex-basis` 写死的宽度），其余用 `width: 100%`；两者同时给 `box-sizing: border-box`，避免内边距把宽列顶出容器产生横向滚动。
- 内联写死的宽度统一改 `width: 100%`（不再用会缩窄的 `auto`）。
- 阅读上限 `READ_W` 1000 → **1500px**，并抽出 `readCap(vw)` 随视口自适应：宽屏取 1500px、窄屏取 88% 视口（下限 900px）。`READ_W` 上提到常量区、CSS 由 `buildCSS` 内插，杜绝「CSS 一个值、运行时另一个值」的漂移。
- 已经够宽的列不写入任何内联样式（避免过度修改 DOM）。

### 验证

回归 **195/195**（新增「文章页加宽（窄列撑满）」场景 11 条）、深度验证 **97/97**（A3b 追加「整脚本真实启动后写死 690px 的列被撑满」5 条）、变异 **15/15 全捕获**、`node --check` 通过、死代码 0、SVG 无溢出。

## v1.4.0 — 2026-09-23

一句话：**放弃「猜类名」，改为不依赖任何类名的几何自适应 —— 补上此前完全缺失的居中动作，清掉为侧栏留位的占位列与不对称内边距，并加入布局诊断回传通道。**

用户在 v1.3.2 之后仍反馈同一篇文章未居中放宽。核验后确认问题不在「判据写错了哪一代」，而在**策略本身**：专栏文章页布局容器的类名三代演进（哈希 `.css-*` → `.Post-Row-Content*` → `.Post-NormalMain*`），写死任何一代都会在别的代上整条落空。

### 根因（本轮三查）

1. **`fixPostLayout` 根本没有居中动作** —— v1.3.2 那版只解 `max-width`、把内联 `width` 改成百分比，**从不设置 `margin`**。等于「把宽度放开了，却没有把位置搬回来」，正文自然还贴着左边。
2. **`.Catalog` 只藏自己、禁止上溯** —— v1.3.2 为「避免上溯藏掉整页」而放弃上溯，结果目录面板的**外层占位列**（常无类名）留在 flex 行里继续占位，正文被挤向一侧、对侧出现大片留白。用户截图正是这个形态：正文列宽 508px、左边缘 182px，而居中应在 286px。
3. **左侧面板的载体从未进入执行层** —— `cleanSticky` 里没有 `.Post-SideActions` 分支。CSS 虽已把它 `display:none`，但**它的外层容器**仍在文档流里占位。

### 修复

- **`fixPostLayout` 重写为几何自适应**（不依赖任何类名）：自正文根 `.ztext` 系列上溯祖先链，逐层 ① 解除窄于 1100px 的 `max-width`、② 内联写死宽度改 `auto`、③ 设双 `auto` 外边距居中、④ 清掉左右不对称（差值 > 40px）的内边距；⑤ 链上最外层收一个 1000px 阅读上限。
- **新增 `hideColumn()` 安全上溯**：从面板标记向上扩张，隐藏「仍不含正文根」的最外层块级容器；**红线是「一旦该容器含正文，立即停止」**。`.Catalog` 与 `.Post-SideActions` 两处判据都改走它 —— 既收掉占位列，又绝不波及正文。
- **新增 `hideNarrowCols()`**：行内「实测宽度 < 320px 且几乎无文字（< 100 字）」的兄弟列判为目录/侧栏占位列并隐藏。以「实测宽度 > 0」作为「环境有布局引擎」的开关，避免无布局环境误判。
- **新增布局诊断（临时）**：判定「自愈后仍偏离居中超过 40px」时，在页顶显示一条细横幅，输出视口宽 / 正文宽 / 左偏移 / 各类名命中情况 / 祖先链（含各层实测宽度）。**页面无横幅即表示布局已判定正常**，因此它自带验收信号；定位完成后移除。

### 验证

回归 **174/174**（新增 15 条：占位列安全上溯、双 auto 居中、阅读上限、不对称内边距清除、`layoutVerdict` 四种判定、无布局引擎时不误报横幅）；深度验证 **92/92**；变异测试全捕获；架构图与 README 已同步。

### 说明

知乎对未登录的自动化浏览器返回反爬空壳（文章页 body 仅 173 字节，`zhuanlan` 直连亦 403），真实页面端到端无法在自动化环境复现；本轮结论来自 ref 源码交叉核验 + 用户截图的几何反推。

## v1.3.2 — 2026-09-23

一句话：**弄清「为什么这类文章就是无法居中放宽」——真凶是目录面板判据整个缺失 + 居中写法依赖父级 display；本轮改用 `.Catalog` 判据、双 auto 外边距居中，并新增运行时上溯解限。**

用户在 v1.3.1 之后复问：`zhuanlan.zhihu.com/p/2000307987458327608` 这类文章**为什么就是无法居中放宽**。逐条核验 `ref/` 后确认为三处判据失配，其中两处是 v1.3.1 修正不彻底所致。

### 根因（本轮三查）

1. **目录面板判据整个缺失。** `ref/知乎优化1.js:10303` 隐藏目录用的是 `.Catalog.isCatalogV2` —— 即**目录面板的根类名是 `.Catalog`**；其内部 `.CatalogModule-title-sggN4` 与 `-9caZz` 两个版本并存，证明模块名后缀是**构建哈希、每发版必变**，故只能认 `.Catalog` 这一层。v1.0~v1.3.1 从未写过 `.Catalog`，还把 `.Post-SideActions` 当成了目录（那其实是**左侧悬浮操作栏**，`ref/知乎优化3.js:385` 给它的规则是 `left: calc(10vw)`）—— 于是目录压根没被隐藏，它继续在 flex 行里占位，把正文挤向左侧。
2. **居中的实现依赖了父级 display。** v1.3.1 写的是 `.Post-NormalMain { margin: 0 auto; flex: 0 1 auto }` 配合父级 `justify-content: center`。这套**只在父级确实是 flex 容器时成立**；一旦正文列的父级是普通 block，或在中间隔着一个无类名的块级 wrapper，`flex` 与 `justify-content` 双双失效，而 `margin: auto` 又因块级元素默认撑满宽度而不起作用 —— 正文于是纹丝不动地贴在左侧。本轮改用**双 `auto` 外边距**（`margin-left/right: auto`）：block 父级下（配合 `width: 100%`）与 flex 父级下（auto 外边距优先吸收剩余空间）**都成立**，不再关心父级是什么。
3. **「放宽」的方向与幅度都不对。** `ref/知乎优化1.js:1001` 的放宽是 `$(".css-c0fani").width($(".css-kjzwqj").width())` —— 取外层容器宽度回写正文列，即**撑满**；v1.3.1 却把阅读宽度限制在 850px，本质仍是「限宽」。

### 修复

- **目录判据**：隐藏列表加入 `.Catalog`（`cleanSticky` 同步标记落幂等）；并明确 **`.Catalog` 只藏自己、绝不上溯** —— 它本身即面板根，上溯会命中含正文的行容器、把整页藏掉；
- **居中写法**：正文列一律改为 `width:100%` + `max-width:1000px` + `margin-left/right:auto`（block / flex 父级通用）；
- **阅读宽度**：850px → **1000px**（正文内容列、评论区、页头同步）；
- **新增执行层 `fixPostLayout()`**：自正文根（`.Post-RichTextContainer` / `.RichText.ztext` / `.ztext`，跨代长期稳定）**上溯**，把沿途窄于阅读宽度的 `max-width` 与内联写死宽度逐级解除 —— 这是 ref `width(外层宽度)` 的结构化等价做法，但**不依赖任何行容器类名**，用来兜住「三代类名」之外的未知中间层。非文章页（无 `.ztext` 系列）直接空转。
- 安全性代价：`.Post-SideActions` 不再上溯（它是定位元素、不占文档流），上溯只保留给 inline 的 `a[aria-label="边栏锚点"]`，避免误伤行容器。

### 验证

回归 **159/159**、深度验证 **91/91**（A3b 场景改为 `.Catalog` 判据，并新增「目录根不上溯」的反向断言）、**变异测试 9/9 全捕获**、`node --check` 通过、死代码 0、SVG 无溢出。

## v1.3.1 — 2026-09-22

一句话：**修正文章页「居中 + 放宽」——补上被漏掉的新代正文宿主，并让侧栏掩盖不再依赖已过时的锚点判据。**

前版 v1.3.0 的居中修复在线上文章页（`zhuanlan.zhihu.com/p/...`）未生效：左侧「目录」面板仍在，正文仍是窄列靠左，右侧大片留白。经对照 `ref/` 参考脚本与第三方长期维护脚本，定位到两处判据失配：

### 根因

1. **正文宿主选择器漏了新代结构。** 知乎文章页有两代 DOM：
   - 新代（当前线上）：`.Post-content` > **`.Post-NormalMain`**（正文宿主）/ `.Post-NormalSub`
   - 旧代：`.Post-Row-Content` > `.Post-Row-Content-left`（正文列）

   v1.3.0 只写了 `.Post-content` / `.Post-Row-Content-left`，**完全没有 `.Post-NormalMain`** —— 新代页面上这两条规则一条都没命中，所以既没居中、也没放宽。（佐证：`ref/知乎优化3.js` 的文章页宽屏样式正文只写 `.Post-NormalMain .Post-Header, .Post-NormalMain > div, .Post-NormalSub > div`。）
2. **目录面板的锚点判据已过时。** v1.3.0 靠 `a[aria-label="边栏锚点"]` 上溯——该 aria-label 属知乎 2021 年前后的旧代结构（`ref/知乎优化1.js` 即此写法），新代目录面板已不再使用，于是上溯逻辑整条落空，目录一直留在页面上。
3. **宽度方向写反了。** v1.3.0 给正文列加了 `max-width: 694px`，这是「收窄」；用户诉求是「居中**放宽**」。

### 修复

- **补全新代宿主**：新增 `.Post-NormalMain` / `.Post-NormalSub` 的居中规则（`margin: 0 auto` + `flex: 0 1 auto` 自适应宽度）；
- **正文阅读宽度放宽**：`.Post-NormalMain .Post-Header` / `.Post-RichTextContainer` / `.Post-NormalMain > div` / `.Post-NormalSub > div` / `.Comment-container` 统一到 `max-width: 850px`（原 690px，长文可读性上限内明显放宽），并去掉 `.Comment-container` 的左右内边距干扰；
- **去掉旧代正文列的写死宽度**（原 `max-width: 694px` → 自适应），居中交由外层 `flex` 完成；
- **侧栏/目录判据改为结构上溯**：`cleanSticky` 的标记集合从「仅旧代锚点」扩为 **`.Post-SideActions` ∪ `a[aria-label="边栏锚点"]`**，两者都走统一的上溯隐藏（隐藏标记元素的最近块级祖先，而非标记本身——目录面板容器常是无类名的内联布局 DIV）；
- 抽出 `hideAncestor(el)` helper，消除上溯逻辑重复，并保证幂等（容器已是 `display:none` 时不重复计数）。

### 验证

- 全量回归 **149/149**（新增 6 条：新代宿主参与居中 / 新代宿主自适应宽度 / 覆盖 `.Post-NormalSub` / 阅读宽度放宽至 850px / 旧代列不再压 694px / 新代无 aria-label 场景下仍能命中目录面板）；
- e2e 新增场景 **6b · 新代文章页**：构造「目录面板无 `a[aria-label]`、只挂 `.Post-SideActions` 且包在无类名 wrapper 里」的真实结构，断言上溯确实藏掉了外层容器；

## v1.3.0 — 2026-09-23

一句话：**修复两处实际使用问题——专栏文章页正文未真正居中、打开知乎时首屏页脚闪现。**

### 修复

- **专栏文章页正文未居中**：原写法把正文列硬压 `690px` 并靠左，右侧留白明显；且左侧「目录」面板因选择器失配未被隐藏，进一步把正文挤出视觉中心。现改为：
  - 正文列不再写死宽度，改为外层 `flex` 居中 + 正文列自适应（`flex: 0 1 auto` + `max-width`），宽度跟随知乎自身内容列；

### 侧栏识别加固

- 侧栏隐藏新增**知乎埋点语义属性** `div[data-za-detail-view-path-module="RightSideBar"]` 作为首选判据——该属性为知乎官方埋点所用，跨改版远比哈希类名稳定（经检索多个长期维护脚本均采用同一属性）；原语义类名与结构特征规则保留为后两轨兜底。

### 功能取舍（ref 脚本 → 本脚本）

- **采纳**：隐藏登录弹窗（纯 CSS）；隐藏侧边栏并居中（两份重复实现合并为一份，取居中策略）；下滚自动隐藏顶栏；回答发布时间置顶 + 「编辑于」补全发布日期；图片原图显示（尺寸后缀白名单剥离，避免误伤 hash）；图片限高；悬停聚焦框；引用角标高亮；GIF 自动播放（默认关）；跳转链接直链化；夜间模式（属性门控方案，切换免刷新）。
