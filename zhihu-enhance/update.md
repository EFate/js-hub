## v1.3.1 — 2026-09-22

一句话：**修正文章页「居中 + 放宽」——补上被漏掉的新代正文宿主，并让侧栏掩盖不再依赖已过时的锚点判据。**

前版 v1.3.0 的居中修复在线上文章页（`zhuanlan.zhihu.com/p/...`）未生效：左侧「目录」面板仍在，正文仍是窄列靠左，右侧大片留白。经对照 `ref/` 参考脚本与第三方长期维护脚本，定位到两处判据失配：

### 根因

1. **正文宿主选择器漏了新代结构。** 知乎文章页有两代 DOM：
   - 新代（当前线上）：`.Post-content` > **`.Post-NormalMain`**（正文宿主）/ `.Post-NormalSub`
   - 旧代：`.Post-Row-Content` > `.Post-Row-Content-left`（正文列）

   v1.3.0 只写了 `.Post-content` / `.Post-Row-Content-left`，**完全没有 `.Post-NormalMain`** —— 新代页面上这两条规则一条都没命中，所以既没居中、也没放宽。（佐证：`ref/知乎优化3.js` 的文章页宽屏样式正文只写 `.Post-NormalMain .Post-Header, .Post-NormalMain > div, .Post-NormalSub > div`。）
2. **目录面板的锚点判据已过时。** v1.3.0 靠 `a[aria-label="边栏锚点"]` 上溯——该 aria-label 属知乎 2021 年前后的旧代结构（`ref/知乎优化1.js` 即此写法），新代目录面板已不再使用，于是上溯逻辑整条落空，目录一直留在页面上。
3. **宽度方向写反了。** v1.3.0 给正文列加了 `max-width: 694px`，这是「收窄」；用户诉求是「居中**放宽**」。

### 修复

- **补全新代宿主**：新增 `.Post-NormalMain` / `.Post-NormalSub` 的居中规则（`margin: 0 auto` + `flex: 0 1 auto` 自适应宽度）；
- **正文阅读宽度放宽**：`.Post-NormalMain .Post-Header` / `.Post-RichTextContainer` / `.Post-NormalMain > div` / `.Post-NormalSub > div` / `.Comment-container` 统一到 `max-width: 850px`（原 690px，长文可读性上限内明显放宽），并去掉 `.Comment-container` 的左右内边距干扰；
- **去掉旧代正文列的写死宽度**（原 `max-width: 694px` → 自适应），居中交由外层 `flex` 完成；
- **侧栏/目录判据改为结构上溯**：`cleanSticky` 的标记集合从「仅旧代锚点」扩为 **`.Post-SideActions` ∪ `a[aria-label="边栏锚点"]`**，两者都走统一的上溯隐藏（隐藏标记元素的最近块级祖先，而非标记本身——目录面板容器常是无类名的内联布局 DIV）；
- 抽出 `hideAncestor(el)` helper，消除上溯逻辑重复，并保证幂等（容器已是 `display:none` 时不重复计数）。

### 验证

- 全量回归 **149/149**（新增 6 条：新代宿主参与居中 / 新代宿主自适应宽度 / 覆盖 `.Post-NormalSub` / 阅读宽度放宽至 850px / 旧代列不再压 694px / 新代无 aria-label 场景下仍能命中目录面板）；
- e2e 新增场景 **6b · 新代文章页**：构造「目录面板无 `a[aria-label]`、只挂 `.Post-SideActions` 且包在无类名 wrapper 里」的真实结构，断言上溯确实藏掉了外层容器；
- 深度验证 `.tmp/verify-zhihu.js` **88/88**（新增 A3b 组：整脚本真实启动后动态插入新代文章页 DOM，等 Watcher debounce 完成，断言目录容器被隐藏 + 常驻 CSS 含新代规则）；
- 变异测试 5/5 全部捕获；死代码 0；`node --check` 通过；架构图标题升 1.3.1。

## v1.3.0 — 2026-09-23

一句话：**修复两处实际使用问题——专栏文章页正文未真正居中、打开知乎时首屏页脚闪现。**

### 修复

- **专栏文章页正文未居中**：原写法把正文列硬压 `690px` 并靠左，右侧留白明显；且左侧「目录」面板因选择器失配未被隐藏，进一步把正文挤出视觉中心。现改为：
  - 正文列不再写死宽度，改为外层 `flex` 居中 + 正文列自适应（`flex: 0 1 auto` + `max-width`），宽度跟随知乎自身内容列；
  - 目录面板用锚点语义定位后在**执行层上溯隐藏其容器**（CSS 无父选择器，`a[aria-label="边栏锚点"]` → 上溯最近的块级容器），与参考脚本 `.closest('div').hide()` 等价但不依赖易变的哈希类名。
- **首屏页脚闪现**：知乎 SPA 在正文水合前会先把页脚（帮助中心/举报中心/备案）渲染出来，表现为「打开时闪一下再消失」。新增启动期标记 `html[data-zhx-booting]`：`document-start` 先藏住页脚（同时覆盖 `<footer>` 与 `.zh-footer`），主内容区一出现即由 `MutationObserver` 解除标记（另设 4 秒兜底，绝不长期遮挡），正常的关于页不受影响。

### 侧栏识别加固

- 侧栏隐藏新增**知乎埋点语义属性** `div[data-za-detail-view-path-module="RightSideBar"]` 作为首选判据——该属性为知乎官方埋点所用，跨改版远比哈希类名稳定（经检索多个长期维护脚本均采用同一属性）；原语义类名与结构特征规则保留为后两轨兜底。

### 验证

- 全量回归 **139/139**（新增侧栏语义属性、正文列不写死宽度、页脚防闪现规则、目录锚点容器上溯 + 幂等 4 项断言）；
- 深度验证 `.tmp/verify-zhihu.js` **87/87**（新增「启动即打首屏标记」「主内容就绪即解除标记」2 条真实启动断言）；
- **变异测试 5/5 全部捕获**（回退侧栏语义属性 / 目录容器上溯 / 正文列宽度 / 启动打标记 / 就绪解除，对应断言均如期 FAIL）；
- 死代码扫描 0；`node --check` 通过；架构图文字溢出校验通过（标题升 1.3.0）。

## v1.2.0 — 2026-09-23

一句话：**原图替换优先信任知乎原生 `data-actualsrc` —— 官方给出的原图地址不再走尺寸后缀剥离，彻底消除「带 hash 的新尺寸参数被误剥」的边界。**

### 功能增强

- **原图识别更准**：知乎图片懒加载会在 `<img>` 上带 `data-actualsrc` 原生原图地址（带 hash 的新尺寸参数也不会被误伤）。新增 `pickOriginal(img)` 纯函数：实际地址与当前 `src` 不同且含 `zhimg.com` 时直接信任 `data-actualsrc`；缺失才回退 `normalizeImg` 尺寸后缀剥离。`applyImg` 改用该入口，`pickOriginal` 补入 UMD 导出。

### 验证

- 全量回归 **129/129**（新增 `pickOriginal` 优先信任 `data-actualsrc` / 缺失回退剥离 2 条断言）；
- 深度验证 `.tmp/verify-zhihu.js` **85/85**（版本断言同步 1.2.0）；
- 死代码扫描 0；`node --check` 通过；架构图文字溢出校验通过（标题升 1.2.0）。

## v1.1.0 — 2026-09-22

一句话：**按「效果最好」增强两处核心功能——直链化补全知乎 `?next=`/`&next=` 编码参数识别；夜间模式输出 `color-scheme` 让原生控件也变深色。**

### 功能增强

- **直链化覆盖更全**：原只认 `link.zhihu.com/?target=` 一种中转形态；现新增识别知乎站内链接携带的 `?next=` / `&next=` 编码目标（最普遍的直跳场景），解码后是 http(s) 且非知乎站内才改写，命中即返回（优先最明确路径）。抽 `safeDecode` / `isForeign` 两个辅助纯函数，并补入 UMD 导出。
- **夜间模式覆盖更全**：`NIGHT_CSS` 增加 `html[data-theme=dark]{color-scheme:dark}` 与 `[data-theme=light]{color-scheme:light}`，让浏览器原生表单/滚动条/弹窗也跟随深色，纯 CSS 无新依赖；比大脚本依赖 jQuery cookie 写知乎自定义开关的方案更轻量普适。

### 验证

- 全量回归 **127/127**（新增 `?next=` / `&next=` / 站内 next 不动 / next 非 URL 拒绝 4 条直链断言 + color-scheme 输出断言）；
- 深度验证 `.tmp/verify-zhihu.js` **85/85**（整脚本 jsdom 真实启动 + 图↔代码↔文档一致性，版本断言同步 1.1.0）；
- 死代码扫描 0；`node --check` 通过；架构图文字溢出校验通过（resolveLink 节点补 `next=` 路径、标题升 1.1.0）。

## v1.0.0 — 2026-09-22

首发版本。整合四个旧知乎优化脚本的可用功能，按「功能必要性 + 最轻量普适实现」去重取舍，四组分类共 11 个开关。

### 功能取舍（ref 脚本 → 本脚本）

- **采纳**：隐藏登录弹窗（纯 CSS）；隐藏侧边栏并居中（两份重复实现合并为一份，取居中策略）；下滚自动隐藏顶栏；回答发布时间置顶 + 「编辑于」补全发布日期；图片原图显示（尺寸后缀白名单剥离，避免误伤 hash）；图片限高；悬停聚焦框；引用角标高亮；GIF 自动播放（默认关）；跳转链接直链化；夜间模式（属性门控方案，切换免刷新）。
- **砍掉**：题目栏注入按钮（举报/匿名/日志/快捷键）、信息流不感兴趣按钮与标签 —— 注入型实现重、随改版易碎，与零打扰原则冲突；隐藏图片/视频、通知气泡等长尾开关 —— 小众且增加设置噪音。

### 架构

- 七层：L1 配置（选项定义表 11 开关 / 4 组）→ L2 数据（设置对象单一数据源）→ L3 样式（按开关拼装，夜间主题常驻由属性门控）→ L4 核心逻辑（直链解析 / 原图归一 / 时间提取，纯函数 UMD 导出）→ L5 执行（DOM 动作全部带幂等标记）→ L6 UI（设置面板懒挂载，管理器菜单是唯一入口，零页面注入）→ L7 Watcher（唯一的监听者：MutationObserver 去抖 + scroll 节流 + 夜间主题守护）。
- 零依赖（不引 jQuery）、零网络请求、`@noframes`。

### 验证

- `node --check` 通过；测试 97/97（smoke：配置表 / buildCSS 逐开关 / 直链解析 12 例 / 原图归一 8 例 / 时间提取 7 例 / 护栏 9 项；e2e：直链化、时间置顶、原图替换、开关门控、sticky 清理五场景含幂等断言；文档核验：README 无版本号、无内部标识符、11 个开关说明全覆盖）。
- 测试揪出并修复三处真实缺陷：原图替换按长度截断误伤扩展名 → 改为整段匹配替换；直链编码兜底会把目标 URL 自身的查询串切掉 → 改为编码态按 `&` 截断后再解码；严格模式下 `arguments.callee` 抛错 → 改具名处理器。
- 架构图 `architecture-diagram-svg/zhihu-enhance-architecture.svg` 与代码同步，文字溢出校验通过。
