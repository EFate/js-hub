# 工程红线与历史事故

本文件记录 js-hub 各脚本开发中真实踩过的坑。**这些不是建议，是事故复盘**——违反其中之一，之前就翻过车。

## 一、工具与编辑纪律

| 红线 | 事故来源 | 正确做法 |
|---|---|---|
| **批量删代码前必须先打印区间内所有定义的符号** | 一次批量删除吞掉了无干系的函数，静默失效且测试没覆盖到 | 先 grep 出区间内所有 `function` / `var` 定义，确认无干系再删 |
| **Edit 工具对文件头部的编辑偶发静默失败** | 改了 Meta 头，实际文件没变，推送后版本号仍是旧的 | 头部改动后**必须 grep 复核**；或改用 node 补丁脚本 |
| **同消息并行 Edit 同一文件会互相覆盖** | 两个 Edit 并行发出，后一个基于旧快照，前一个改动丢失 | 同一文件的多处改动串行；或写一个 node 补丁脚本一次改完 |
| **补丁脚本必须锚点唯一性断言** | 锚点出现两次时 `replace` 只改了第一处，第二处静默漏改 | 补丁里 `n !== 1 即 exit`，改完回读校验 |
| **CRLF 文件里多行锚点用 `\r\n` 拼接** | 锚点用 `\n` 拼，永远命中不了，补丁静默不生效 | 先探测文件换行符，按实际换行符拼接 |
| **`querySelector` 避免 `:has()`** | 旧内核浏览器直接抛异常，整段脚本死掉 | 用纯函数遍历判定，或在 `try/catch` 里禁用该分支 |
| **bash 缺 coreutils，命令行传中文有编码坑** | 补丁内容经命令行传输变乱码，写进文件后语法错 | 全程 `node -e` 或独立补丁脚本文件，中文不经过 shell 参数 |

## 二、测试假绿五型（变异测试就是为抓它）

只跑「全绿」不算数——**断言可能根本没在测东西**。把修复点回退，断言必须变红；不变红 = 假绿。

| 型 | 表现 | 修法 |
|---|---|---|
| ① 断言匹配到注释/全局单值 | 断言 `src.indexOf('xxx') > -1` 命中的是注释里的字样 | 断言锚定具体声明块或行为出口 |
| ② 数值断言未锚定选择器声明块 | 断言「宽度是 1200px」，命中的是另一个选择器里的 1200 | 把断言范围切到具体规则块内 |
| ③ 夹具信号重叠 | 两个分支互相兜底，删掉一个分支测试照样过 | 让两分支的信号互斥，一个夹具只触发一个分支 |
| ④ 夹具数值与视口耦合 | 夹具用了恰好卡在阈值上的值 | 取恒大于/恒小于阈值的数 |
| ⑤ 依赖「阈值 vs 视口」关系却没固定视口 | 环境变了断言含义就变了 | `Object.defineProperty` 固定 `innerWidth` |

**验证流程**：改断言 → 回退修复点 → 必须 FAIL → 还原 → 必须 PASS。一个都不能省。

## 三、识别类脚本的专项红线

- **测量代码必须与修复代码共用判据**。分别写两份判定，迟早分叉——一份说「这是正文」，另一份说「这不是」，横幅就开始误报。
- **一票否决优先于证据**：路径级否定（如 `/question/` 绝不按文章页处理）必须压过元素级证据，证据类救不回来。
- **识别类改动必须过真实 HTML 端到端**，纯函数冒烟不够。真实页面会用组合结构打脸你的选择器。
- **夹具必须来自真实页面结构**，不能凭想象造。真实站点有风控抓不到时（如百度安全验证页），用已知的真实结构片段构造夹具，并在文档里写明这个替代关系。

## 四、DOM 与渲染陷阱

| 陷阱 | 说明 |
|---|---|
| `width:auto` 在 flex 行内反向 | 想让元素变宽时 `width:auto` 会被内容宽度锁死，需 `flex-grow:1` 或 `width:100%` |
| `querySelector` 只认文档序 | 想找「文本最多的正文根」，靠选择器顺序不可靠，得遍历打分 |
| jsdom 没有布局引擎 | `getComputedStyle` 返回内联样式值可单测，但实测宽度恒为 0 —— 涉及布局的判据要以「实测宽 > 0」当布局开关 |
| `document-start` 时 `head` 可能未就绪 | 样式先挂 `documentElement`，`DOMContentLoaded` 后归位 `head` |
| 延迟回调触发时必须复检判据 | 异步渲染后原本「没命中」的判据可能已成立，直接执行会造成误处理 |

## 五、分发与版本

- **只改不推 = 用户永远旧版**。`@updateURL` / `@downloadURL` 缺失时脚本管理器不会检查更新。
- **本仓库 `packed-refs` 可能假 ahead**，`git status` 显示领先但远端没变。推送状态第一判据是 `git ls-remote origin main` 对照本地 HEAD。
- **raw CDN 会限流**（429 限流 / 连接断 http=000）。改用 contents API 拉 blob 解码核验：
  `GET /repos/<owner>/<repo>/contents/<path>?ref=main` → base64 解码 → 比对 `@version` 与修复特征串。首次 `ECONNRESET` 属常态，包 3 次退避重试。
- **版本号有两处**：Meta `@version` 与代码内 `VERSION` 常量，必须同步；架构图标题版本号是第三处。
- **预览/文档被版本号引用时要重跑**：面板预览 HTML、文档核验脚本里的版本字面量断言，升版后都得更新。

## 六、入口红线（最常被违反）

- 悬浮球、圆角胶囊、侧边吸附按钮、可拖拽常驻按钮 —— **一律禁止**，遮挡内容且制造视觉噪音。
- 全局 `keydown` / `keyup` 监听 —— **一律禁止**，与宿主站点、浏览器、其它扩展冲突。面板打开后的 `Esc` 关闭是唯一例外。
- 注入前必须回答两问：**页面上有需要用户点一下的动作吗？入口出现后用户能拿它做什么？** 两问都答「没有」→ 零注入。
- 判为零注入的脚本，连「显示入口」设置都不该有——给一个永远不该出现的按钮配开关，是把噪音写进设置页。
- 注入式入口必须挂进宿主既有容器（`position: static/relative`），尺寸向邻居看齐，等容器出现再注入，防重复注入，并保留管理器菜单兜底。
- **按需注入档必须告知状态**：按钮没出现时用户会问为什么，面板要明示判定结果与具体原因。
